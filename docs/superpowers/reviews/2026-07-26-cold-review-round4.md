### W4-1 — CRITICAL, PROVEN: removing the RCD floor exposed a non-negative-input assumption — unbounded negative spikes reach the saved master
`Debayer.swift:233-236` (exposed by the `:403-405` clamp change). RCD's green-estimate ratios have denominators `EPS + lpf_i + lpf_Ni` where the lpf terms are positively-weighted neighborhood sums — non-negative in rcd.cc's world, but symmetric about 0 for dark-subtracted data, so the denominator crosses zero and the estimate blows up with either sign. The old `max(0,·)` **masked** the blowups; now only the +1 cap remains, so negative spikes pass unbounded. Measured: single-frame interior min **−628** (−1513 with stars); through the real StackEngine, stack min −70.6 (norm off) and **−7.7 with the full default config** — sigma-clip attenuates but can't reject warm-up spikes; ~1 in 1200 non-star pixels below −0.05. These reach master.fit unclamped (float32 write path verified clamp-free); display shows black speckles. Bilinear control: min −0.013, zero outliers.
**Fix shape, empirically proven by the reviewer:** pedestal the demosaic — `rcd(cfa + 0.5) − 0.5` on the same input gives range [−0.083, +0.092], G median −3e-4: spike-free AND bias-free. (Sign-safe denominators are the deeper alternative.) **Test gap:** nothing bounds RCD output on zero-mean input — the −628 spikes pass the whole suite silently; add that bound alongside the existing bias-pinning test.

### W4-2 — HIGH, PROVEN (three coordinated probes, two independent reviewers): per-victim clocks fixed the blocker side but the victim-side clock lifecycle is wrong
`WatcherFileState.swift:416-418, 511-537, 554-558, 600-612`.
- **Stale clocks age while unblocked / survive episode dissolution.** Clocks are cleared only on file absence and write-off; neither dissolution path (blocker resolves/vanishes; blocker-with-no-victims) clears them, and the retention filter keeps every present file. Proven consequences: a victim writes untroubled for 100s with its clock intact, then a genuinely fresh **converging** blocker appears → written off **2.0s** later with zero grace and a log claiming it "blocked for 106s" — frame permanently lost (frame-loss variants reproduced with emission history and via padding twin). Cold reviewer's independent variant: blocker vanishes, file sits head-of-line 38s, a late lower revision appears → **written off in its first batch** ("blocked for 40s" on first sight); milder form silently shortens a fresh blocker's budget from 30s to ~20s.
- **Victim flicker still starves (round-1 S5, unfixed — and now pinned as intended by a test).** One absent scan destroys the clock; a victim absent 1 scan in 10 was never emitted in 800s with zero write-offs (identity-churn variant v_10↔v_010 likewise). `testVictimDisappearanceDestroysEpisodeAndReappearanceStartsFresh` pins destroy-on-absence as the intended semantics — this is now an explicit design decision to revisit, not an oversight.
**Fix shape (both reviewers converge):** a victim's clock should **pause** (not be destroyed) on transient absence, **stop aging** whenever the file is not currently behind a live blocker, and be **cleared on episode dissolution/emission**. Also: round-3's F4 regime is unchanged at 4.0s (arguably correct under victim-centric semantics — the victim really did wait; document it); `isSameNumericRevision` is now dead code; `&+` deadline wrap is unreachable-theoretical.
