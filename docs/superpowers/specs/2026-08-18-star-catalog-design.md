# Star Catalog (plate-solve sub-project 1) — Design

**Date:** 2026-08-18 · **Status:** draft (defaults chosen while user away), pending user review
**Parent pillar:** native plate-solve / north-up (3 sub-projects: **catalog** → solver → apply-north-up).
**Goal:** A bundled, queryable bright-star catalog the solver can match detected stars against — the
low-risk data foundation for the plate-solver.

## Scope (this sub-project only)

A compact all-sky bright-star catalog (RA/Dec/magnitude), bundled as a package resource, with a
loader and a spatial query ("catalog stars within a radius of a sky position"). NO solving, NO
rotation — those are sub-projects 2 and 3. This piece is pure data + query, independently testable.

## Source: Gaia DR3 (same public catalog Siril uses)

Per the user: use the same public source Siril uses. Confirmed from the local Siril install —
Siril's local plate-solve catalog is `siril_cat_healpix8_astro.dat`, header **"Siril Gaia DR3
astrometric extract"** (HEALPix level-8 indexed). So the source catalog is **Gaia DR3** (ESA/Gaia/DPAC,
public, freely usable with attribution — the same attribution Siril carries).

**Bundling reality:** Siril's full Gaia DR3 extract is **~1.4 GB** — a user-downloaded local catalog,
NOT bundled in Siril's app, and far too large to bundle in LiveAstro. The resolution: bundle a
**bright subset of the same Gaia DR3 catalog** (G ≤ **8.5**, all-sky, ~40–60k stars, ~0.5–1 MB) —
sufficient for LiveAstro's known-scale wide-FOV solve (Seestar ~1.3°, ASI2600MC-Air ~2–3° → ~10–30
catalog stars per frame). Same authoritative catalog Siril trusts, at a bundleable size.

- **Depth:** Gaia DR3 G-magnitude ≤ **8.5**, all-sky (flag to change).
- **Format (our bundled subset):** little-endian binary, sorted by declination: a small header
  (magic, version, count) then fixed 12-byte records `{ra: Float32 deg, dec: Float32 deg, mag: Float32}`.
  Float32 sky positions are ~arcsec-precise — ample for a wide-FOV known-scale solve. Sorted-by-dec
  enables an early-exit band scan. (This is OUR compact format, not Siril's HEALPix-8 format — we only
  reuse Siril's DATA/source, not its file layout; HEALPix indexing is overkill at ~50k bright stars.)

## Components

- **`CatalogStar`** (`Sources/LiveAstroCore/PlateSolve/CatalogStar.swift`) — `struct CatalogStar {
  let ra: Float; let dec: Float; let mag: Float }` (celestial degrees). Distinct from `StarDetector.Star`
  (screen-space `{x,y,flux}`); the solver projects catalog→screen later.
- **`StarCatalog`** (`Sources/LiveAstroCore/PlateSolve/StarCatalog.swift`):
  - `init(data: Data)` / `init(contentsOf: URL)` — parse the binary (validate magic/version;
    throw a typed error on a truncated/wrong blob).
  - `static func bundled() -> StarCatalog?` — load from the package resource (nil if the resource
    isn't present, so the app degrades gracefully before the data file is generated).
  - `func stars(nearRA ra: Double, dec: Double, radiusDegrees: Double) -> [CatalogStar]` — return
    all catalog stars within `radiusDegrees` angular separation. Uses unit-vector dot-product for
    separation (correct across the RA 0/360 seam and near the poles — no naive RA-delta wrap bug),
    with a declination-band early-exit (candidates have `|dec − center.dec| ≤ radius`) so a 2° query
    scans a thin band, not the whole catalog. Linear within the band is ample at this size.
  - `var count: Int`.
- **Catalog generator** (`Scripts/generate_star_catalog.py`) — produces
  `Sources/LiveAstroCore/Resources/brightstars.bin` (Gaia DR3, G ≤ 8.5) from EITHER input:
  1. **Siril's local extract** (`~/Desktop/gdr/dr3/siril_cat_healpix8_astro.dat`, which the user
     already has) — parse Siril's documented (GPL) Gaia DR3 record format, keep G ≤ 8.5, repack. No
     network; literally the same data Siril solves against.
  2. **VizieR Gaia DR3** (`I/355`) bright-subset query (`Gmag ≤ 8.5`) — a CSV fetch, simplest to
     parse; needs network once.
  The generator picks whichever input is available, documents the Gaia DR3 source + attribution, and
  is deterministic. The produced ~0.6 MB binary is committed as the bundled resource.
- **Package.swift** — declare `Sources/LiveAstroCore/Resources/brightstars.bin` as a bundled resource
  for the `LiveAstroCore` target (same `Bundle.module` mechanism as the app's `Help.md`).

## Data acquisition (the one real dependency — flag)

The bundled binary must be produced from a public catalog before `bundled()` returns non-nil. This
is a one-time, network-dependent generation step (run the generator, commit the ~0.6 MB binary). The
Swift code (loader + query + generator) is what this sub-project builds and tests; the data artifact
is generated by running the committed generator. If fetching the real catalog is deferred, the loader
+ query are still fully testable against a synthetic catalog, and `bundled()` returns nil (graceful).

## Testing

- **Round-trip:** write a small synthetic catalog (a handful of known `{ra,dec,mag}`) to the binary
  format, load it, assert `count` and exact records back.
- **Header validation:** a truncated / wrong-magic blob throws the typed error (no crash).
- **Spatial query — correctness:** for a synthetic catalog with stars at known separations from a
  center, `stars(near:…radiusDegrees:)` returns exactly those within radius, excludes those outside.
- **Spatial query — seam & poles:** a query centered near RA 0h returns stars at both RA 359.x and
  0.x (dot-product separation, not RA subtraction); a near-pole query returns the right stars despite
  RA convergence.
- **Bundled (gated):** if `brightstars.bin` exists, `bundled()` loads it and `count > 10_000` and a
  query at a dense region (e.g. galactic plane coords) returns a plausible non-empty set. Skipped
  (XCTSkip) when the resource isn't generated yet, so the suite stays green pre-data.

## Non-goals (this sub-project)

- The solve itself (triangle-match, WCS recovery) — sub-project 2.
- Any rotation / north-up / UI — sub-project 3.
- Proper-motion epoch correction, color indices, multi-band mags (bundle only RA/Dec/mag).
- A k-d tree / HEALPix index — a dec-band linear scan is ample at ~50k stars (YAGNI; revisit only if
  the solver needs deeper catalogs).

## Expected result

`StarCatalog.bundled()?.stars(nearRA:dec:radiusDegrees:)` returns the bright catalog stars in any
sky region in well under a millisecond — the queryable foundation sub-project 2's solver matches
detected stars against. Zero external runtime dependency (data bundled); zero-dep preserved.
